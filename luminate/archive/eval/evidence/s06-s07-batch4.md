# S6. Extensibility, events, API quality

## Outbound events / webhooks
- **No outbound webhook module exists** in the 264-package install (only a payment gateway callback). The Templates engine binds **54 events** to channels, but the only channels are **Email, SMS, PDF** (no HTTP channel). Verified via `GET /api/admin/templates/events`.
- The event surface itself is rich and cleanly modelled (Laravel events carrying `user` + model): courses 14 (`CourseAssigned`, `CourseUnassigned`, `CourseStarted`, `CourseFinished`, `TopicFinished`, `LessonFinished`, ...), auth 15, quiz 5 (`QuizAttemptFinishedEvent`, `QuizAttemptJournalGradeReadyEvent`, ...).
- **I built the bridge to measure extension effort**: a Composer package `luminate/wellms-webhooks` (3 PHP files, ~150 lines): service provider (listens to 6 events), a synchronous listener that builds the payload, and a queued job that POSTs JSON with `X-Wellms-Event`, `X-Wellms-Delivery`, `X-Wellms-Signature: sha256=HMAC`. Installed with `composer config repositories.x path /opt/...; composer require luminate/wellms-webhooks:@dev`; Laravel package auto-discovery registered it with no change to Wellms code (Verified). Per-tenant URL/secret via per-domain env (`LUMINATE_WEBHOOK_URL`).
- Delivery test (tenant A, receiver on host): `enrolment.created`, `topic.completed`, `quiz.grade.ready`, `quiz.attempt.finished`, `course.completed`, `enrolment.removed` all arrived signed, ~2 to 5 s after the action. Receiver-forced failures (HTTP 500 x2) were retried at +5 s and +21 s, delivered on the 3rd attempt with the **same delivery id** (de-duplication possible).
- **Platform defects found while doing this (Verified):**
  1. **Queued listeners on `Course*` events are broken**: `Course` is an abstract class with `private` `$user`/`$course` + `SerializesModels`; a queued listener receives an uninitialised object (`Typed property ...Course::$user must not be accessed before initialization`) for CourseAssigned/Finished/Unassigned/Started/etc. `TopicFinished` (properties declared on the class itself) works. Workaround: read the event synchronously and queue a job of plain values (what the package does).
  2. **Quiz events fire before the score exists on the object**: `result_score`, `result_percent`, `is_passed` were `null` in the event payload; the API returned 4/4, 100%, passed afterwards. Integrator must "event, then read `GET /api/admin/quiz-attempts/{id}`".
  3. **Ordering is not guaranteed** (3 workers): `quiz.grade.ready` arrived before `quiz.attempt.finished` in the same second.
  4. **Unenrolling emits `CourseFinished` unconditionally** (`CourseAccessService::dispatchEventForUsersDetachedFromCourse` fires CourseUnassigned *and* CourseFinished): a spurious `course.completed` for every removal. Consumers must key on progress, not this event, or suppress it.
  5. **Failed jobs are not recorded**: `config/queue.php` uses the legacy `database` failed-job driver but `failed_jobs.uuid` is NOT NULL; every failure raises `null value in column "uuid"` while being recorded, so failed jobs vanish (`failed_jobs` stayed empty with 24+ failures logged). Operators lose retry/diagnostic visibility.

## Pagination, filtering, bulk, idempotency, errors, versioning (tenant B)
- Pagination: Laravel paginator in `{success,data,meta,message}` with `current_page, from, to, last_page, total, per_page, links, next_page_url`. Page-number only (no cursor). **No page-size cap**: `per_page=100000` returned all 62 rows; `per_page=-5` returned all; `per_page=0` returned default 15; **`per_page=abc` -> HTTP 500 TypeError**; page beyond last -> 200 with empty data.
- Filters (users): `search` (substring), `role`, `status`, `from/to` (created date), sort via `order_by`/`order` works though not in the spec; **unknown filters are silently ignored** (HTTP 200). Courses: `title, category_id, authors, tag, free, status, group_id, order_by` per spec; **no custom-field filter** (from S4).
- Bulk: `POST /api/admin/csv/users` (needs `file` + `return_url`) imported 60 users in 8.9 s synchronously, but **imported users get no role (`roles: []`) and cannot log in (HTTP 403)**; role assignment from the CSV not found (Unknown). Bulk enrolment: `access/add` with 50 user ids in one call, 1.5 s; repeating it is **idempotent** (still 50); one unknown id fails the whole call with 422 (`users.0` index), all-or-nothing. Exports exist for quiz attempts, stats, orders, courses (xlsx/zip).
- Idempotency: duplicate email -> 422; **`Idempotency-Key` header ignored** (two identical POSTs created two courses, ids 4 and 5; deleted afterwards). No optimistic concurrency/ETag.
- Error semantics: **at least five body shapes**: `{message}` (401), `{error}` (403), `{message,success}` (404 model), `{message,errors}` (422, incl. malformed JSON), and raw exception dumps (404 route, 405) with `exception/file/line/trace`; `GET /api/admin/users/abc` returned HTTP **423** non-JSON. Stack-trace/path leakage is due to the reference compose setting `LARAVEL_APP_DEBUG=true` (production setting not tested).
- **No rate limiting seen**: 15 rapid bad logins all returned 422 (no 429, no `X-RateLimit-*` headers) (15 attempts only).
- Versioning: no `/v1` prefix (404), OpenAPI `info.version` 0.0.1, no API-version header. CORS `Access-Control-Allow-Origin: *`. OpenAPI paths wrong for impersonate and all `hh5p` admin routes (seen in earlier batches).
- SDK: `escolalms/sdk` and REST docs referenced by the brief: **Documented only**, not exercised.

## How a custom module / field is added (Verified)
- Custom *fields*: runtime, via `POST /api/admin/model-fields` (S4), no deploy.
- Custom *behaviour*: standard Laravel/Composer package with a service provider, auto-discovered; can listen to any domain event, add routes, permissions seeder (pattern used by every `escolalms/*` package). Effort for the webhook bridge: roughly half a day including debugging the two platform defects above. Packages are deployed by baking into the Docker image (I installed into a running container for the test, which does not survive recreate).

Verdict S6: **Partial**: strong event model and a conventional extension path, but no outbound webhooks (must build and operate), several defects in the event/queue plumbing, inconsistent error shapes, no rate limit, no idempotency keys, no versioning.

# S7. Media (tenant B)
- Backend: **S3-compatible (MinIO)**, bucket per tenant, selected by `FILESYSTEM_DRIVER=s3` (Verified). Key layout `course/{courseId}/topic/{topicId}/{type}/{random}.{ext}`, course images `course/{id}/images/..`, resources `.../resources/notes.pdf`.
- Uploads via REST multipart (Verified): topic **Video** (mp4, 201; ffprobe extracted 320x240, 4000 ms), **Audio** (mp3, 201), **PDF** (201, `page_count` computed), course `image`/`poster` (200), topic **resources** (201), file manager `POST /api/admin/file/upload` (200; list needs `directory` param). Server limits `upload_max_filesize=post_max_size=2G`, no Caddy body limit; chunked/resumable upload not found (Unknown).
- **Image topic upload returned HTTP 500**: `getimagesize(http://storage.localhost/tenant-b/...): Connection refused`; the backend re-reads the file it just stored via its **public URL**, which the API container cannot reach in this Docker setup. Needs the public storage host resolvable from the API container (environment coupling).
- **URL strategy = public object URLs** (`http://storage.localhost/<bucket>/<key>`); no presigned/temporary URL support found in the vendor code (grep for `temporaryUrl`/`presign` empty). Both the stock `wellms` bucket and tenant buckets are **private by default**: anonymous GET -> 403. Made `tenant-b` public temporarily: anonymous GET 200 with correct MIME and **Range requests return 206** (seekable), then restored private. Consequence: either public buckets (no per-user protection for paid/private courses) or build an authenticated media proxy / signed-URL layer.
- **Video transcoding did not run**: only the original MP4 exists; topic JSON stays `{"ffmpeg":{"state":"queue"}}`. Cause (Verified): `ProcessVideo` is queued on connection `redis-long-job`, queue `queue-long-job`; it sits in Redis (`queues:queue-long-job` len 1) and the multi-domain workers only listen to `default,broadcast,video`. In multi-domain mode nothing consumes it. ffmpeg/ffprobe are present in the image. HLS output (`hls`, `hls_url`, `poster` fields exist) therefore unverified: Unknown.
Verdict S7: **Partial**: upload API and S3 backend are solid; delivery/protection (public URLs only), image-topic coupling and video transcoding in multi-tenant mode need work.

# Cross-cutting finding promoted from this batch: tenant isolation of background jobs (affects S3/Objective 2)
- Queue keys are **not tenant-prefixed** (`queues:default`, `queues:default:delayed`, `queues:queue-long-job`; `config/database.php` has no Redis prefix, queue connection `redis` uses `REDIS_DB` default 0). Multi-domain workers (`queue.sh`) loop over all tenants and any worker pops any tenant's job.
- **Proven**: stopped workers, tenant A queued its delayed `MarkAttemptAsEnded(3)`; ran a worker for tenant B only; it executed A's job against **B's database** and set B's unrelated attempt 3 `end_at` from `2026-10-09 00:44` to `2026-10-08 14:45:47` (data corruption by id collision). Webhook jobs from A were also consumed by B's worker (harmless there because they were self-contained).
- **Mitigation proven**: per-tenant `REDIS_DB` (A=2, B=3) in the tenant env. Repeat run: B's worker ran nothing, B's attempt 6 untouched; A's own job processed in 2 s. Not mentioned in the multidomain docs (Verified by reading `docs/multidomain.md`); not set by the stock init script. Cache DB (`REDIS_CACHE_DB` default 1) is also shared; cache keys are namespaced by app name (Documented, not tested). Redis logical DBs are limited (16 by default), so this does not scale to many tenants without separate Redis instances or code changes (Documented).
